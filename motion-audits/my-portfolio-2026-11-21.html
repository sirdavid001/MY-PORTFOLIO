First fixes

Review the CV data shipped to browsers, preserve client-selected budgets, and make the project screenshots and contact form reliable through loading and narrow layouts.

Project findings

High

CV details are part of the public frontend bundle

The live JavaScript bundle includes the values for date of birth, full contact address, and personal phone fields. A visitor can receive these fields by loading the site, independently of the public CV download. The generated PDF also displays them.

Recommended change Use a small public profile module for the site. Keep full résumé details server-side and decide which fields belong in a public CV.

shared/cv/profile.js:17 · src/pages/Home.jsx:20 · api/cv-download.js:22

High

Location detection can change a budget already selected

With location detection delayed in Chrome, selecting the UK and the first tier displayed £270–£540. The location response changed the country to the US and the same selected tier to $250–$500. Japan also inherited USD from a US visitor because its currency is absent from the mapping.

Recommended change Apply automatic detection only before a manual choice, and use a complete country-to-currency mapping or display the chosen fallback currency explicitly.

High

Project screenshots can stay hidden after they load

The prerendered cards set their images to opacity: 0 until a React load callback runs. Local Chrome reproduced transparent images with valid dimensions on direct navigation. The screenshots were visible on the live sample. All four are hidden when JavaScript is disabled. Forced image failure kept four animated placeholders visible.

Recommended change Render screenshots visible by default, reserve space with dimensions, and give load errors a visible terminal state.

High

Contact overflows a narrow mobile screen

At a 320 px viewport, Contact had a document width of 365 px in Chrome. The Contact sidebar extends past the viewport. Home and Projects fit the same width.

Recommended change Allow both grid children to shrink, reduce card padding at narrow widths, and wrap long contact links.

Medium

Saved dark mode breaks hydration

Opening each prerendered route with a saved dark preference produced React error #418. Static HTML renders the light-mode icon and the first client render expects the dark-mode icon. React recovers by rendering again on the client.

Recommended change Align the prerendered markup with the first React render and apply the saved preference through a hydration-safe theme setup.

Medium

The live fallback returns a soft 404

On the deployment, a missing route returned 200 with the homepage title and canonical URL. The three known routes returned 200 with their own canonical URLs.

Recommended change Serve the prerendered routes directly and return HTTP 404 with a real error page for unknown paths.

Medium

Mobile navigation and CV controls omit keyboard feedback

The mobile menu exposes neither its open state nor a controlled region. Escape left it open, and expanding the viewport while the menu was open left body scrolling locked. The CV format selector computed an outline of none and no box shadow on keyboard focus. The CV email result has no live region.

Recommended change Provide disclosure state and Escape handling, clear the scroll lock when the desktop layout takes over, and add visible focus and an announced result to the CV controls.

Medium

Contact has a dark-mode contrast failure

Axe measured 3.67:1 on the Portfolio link, below the 4.5:1 AA threshold for its text. Axe also flagged the shared footer heading jump across all scanned layouts.

Recommended change Use the foreground token paired with the primary color and place the footer headings at the appropriate level.

Medium

Local email setup is easy to misconfigure

The repository does not ignore .env.local. The README also lists RESEND_FROM_NAME although the route sender names are now fixed. Local browser tests verified the missing-configuration responses and simulated Resend confirmed handler payloads.

Recommended change Ignore local credential overrides and document the sender address and display-name behavior the code uses.

Opportunity

Home gives the evidence less space than the introduction

The opening screen gives visitors your name and a route to the work. The long Home page follows with generic approach cards and a technology list before the CV. The Projects page already has four real screenshots and direct access to the work.

Recommended change Bring one named project and a specific contribution or outcome into the first screen. Give CV access a shorter path and keep the existing direct project and contact actions.

Medium

Project screenshots are large and all load eagerly

The browser performance check recorded about 3.6 MiB of images across four PNGs at both 390 and 1440 px. QuickPOS serves a 3840 px capture for a 356 px card on mobile. The cards reserve space with aspect ratios and could use responsive sources and lazy loading.

Recommended change Measure WebP or AVIF variants at card widths, declare dimensions, and defer below-fold images.

Opportunity

Document export works, with accessibility and format tradeoffs

The live PDF and Word endpoints returned 200. The live PDF matched the locally rendered two-page A4 document byte for byte. It has clear sections and selectable text. PDF tagging is absent. The .doc payload is HTML formatted for Word. Native Word rendering remains unverified.

Recommended change For accessible or strict document workflows, generate a tagged PDF and an actual .docx.

Verification

I used the installed frontend design, Design Taste, UI/UX Pro Max, Design Motion Principles, Web Accessibility, Web Interface Guidelines, and shadcn/ui form guidance, with Vercel and PDF checks for the deployed site and CV.

  • All nine automated tests passed. The build generated distinct HTML and canonical URLs for Home, Projects, and Contact.
  • Chrome covered all three routes at 320, 390, and 1440 px, plus saved dark mode, keyboard navigation, and reduced motion. Axe ran at 390 and 1440 px and on the dark desktop views.
  • Production GET requests returned 200 for all three pages and both CV formats. The four featured demos responded over HTTPS. The UKM card begins with an HTTP link and can link directly to HTTPS. The PDF was rendered locally and the Word file type was checked from its payload.
  • Local browser and API checks covered the download handlers, contact fallback, location, and mocked Resend delivery. Production email receipt and native Word rendering remain unverified.
  • Design Taste’s consistency scan flagged the generic headline and opening layout. Its layout script expects a .wrap container from its own templates. Chromium measurements and screenshots supplied the responsive evidence.
